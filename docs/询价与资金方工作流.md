# 微信询价与资金方选择工作流

这套引擎适合“固定政策 + 临时询价”的报价模式，但两类信息必须分开管理。

## 一笔报价怎样完成

1. 销售录入客户需求：车型、数量、目的地、贸易方式、交付地点和原始付款条款。
2. AI 把付款条款拆成定金比例、尾款触发点、账期和支付方式。
3. 调用 `screen_funders`，从已批准的资金政策中列出符合项和淘汰原因。
4. 采购人员分别向车源、仓储、国内物流和国际物流供应商询价。
5. 把有效微信回复整理成供应商报价行，保留供应商、时间、有效期、经办人和私有证据引用。
6. 系统组合可兼容的车源、运输和资金方案。采购或资金负责人确认入选项。
7. 调用 `validate_quote`；存在过期、缺项、冲突或不适用资金方时停止正式报价。
8. 调用 `calculate_quote` 和 `compare_quotes`，由人选方案后生成对客稿与 MOSS 填写包。

## 固定信息放哪里

资金方利率、服务费、适用贸易方式、可接受的尾款节点、最低定金和最长账期放在私有规则包：

```json
{
  "funding_options": [
    {
      "id": "funder-a",
      "name": "资金方 A",
      "status": "confirmed",
      "fee_rule_ids": ["funder-a-interest"],
      "match": {
        "trade_terms": ["FOB", "CIF"],
        "balance_triggers": ["before_arrival"],
        "payment_methods": ["TT"],
        "min_deposit_rate": "0.2",
        "max_credit_days": "30"
      }
    }
  ]
}
```

示例见 [`examples/funding-rules-candidate.json`](../examples/funding-rules-candidate.json)。公开示例是 `pending`，不能直接作为公司政策加载。真实政策必须按规则审批流程生成新版本。

客户付款条件要同时保留原文和结构化结果：

```json
{
  "payment_terms": "20%定金，车辆到港前付清尾款",
  "customer_payment": {
    "deposit_rate": "0.2",
    "balance_trigger": "before_arrival",
    "credit_days": "30",
    "method": "TT"
  }
}
```

付款原文不清楚时，AI应列为缺项让销售确认，不能自行解释成对资金方更有利的条件。

## 微信供应商报价怎样录入

每个报价候选至少保存：

```json
{
  "source_type": "supplier_quote",
  "supplier_id": "vehicle-supplier-a",
  "supplier_name": "车源商 A",
  "quoted_at": "2026-09-18T10:00:00+08:00",
  "quote_channel": "WeChat",
  "quote_ref": "private://wechat/2026/quote-a.png",
  "owner": "采购负责人",
  "source": "private://wechat/2026/quote-a.png",
  "status": "confirmed",
  "valid_until": "2026-09-20"
}
```

`quote_ref` 指向公司受控目录中的截图、导出记录或转存文件。公开仓库和对客报价中不能出现真实微信截图、联系人、供应商底价或内部链接。

采购人员应额外确认车型配置、含税口径、提车地点、数量、是否含运输、库存真实性和交期。仓储与物流还要确认计费单位、免费期、装卸、保险、发票、路线和异常费用。

## 多供应商怎么比较

把各供应商整理成 `options.vehicle`、`options.transport` 和 `options.funding`。`requires` 表示必须搭配的方案，`excludes` 表示不能同时选择的方案。引擎最多组合 100 个方案，避免在大量无效候选上盲目排列。

系统会保留 `selected_options` 和 `selected_funder_id`。候选报价不会因为价格最低就自动成为正式成本；采购或资金负责人确认后才计算并形成快照。

## 推荐对 AI 说的话

> 按询价工作流处理这个客户需求。先拆解付款条件并调用 screen_funders，展示符合和被排除的资金方及原因。然后整理采购同事提供的微信询价，逐条保留供应商、时间、有效期、经办人和私有证据引用。不要猜缺失价格，也不要把未入选候选计入成本。生成方案后先校验，再计算比较，最后准备对客报价和 MOSS 填写包。
